# نبض الذهب

لوحة React لمتابعة السعر الفوري XAU/USD، تسجل الأسعار والتوصيات محليًا في SQLite، وتتابع نتيجة التوصية المفتوحة.

## المتطلبات والتشغيل

يتطلب Node.js 22.13 أو أحدث.

## تجهيز MongoDB Atlas وترحيل البيانات

لا تضع رابط Atlas أو كلمة المرور في المحادثة أو المستودع. أضفهما محليًا إلى `.env`:

```env
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster-host>/
MONGODB_DATABASE=gold_signal
```

استبدل القيم بين الأقواس من إعدادات Atlas، وتأكد من إعداد Database User وNetwork Access في Atlas. شغّل الترحيل بعد إيقاف الخادم حتى لا تتغير قاعدة SQLite أثناء النسخ:

```bash
npm run migrate:mongodb
```

الأداة تنقل جداول SQLite التسعة إلى مجموعات تحمل أسماءها نفسها، وتحافظ على المفاتيح والسجلات. هي لا تحذف بيانات من Atlas؛ إذا وجدت سجلات متعارضة أو سجلات إضافية، تتوقف بدل استبدالها. يمكن فحص الاتصال وتوافق البيانات دون كتابة باستخدام `npm run migrate:mongodb -- --dry-run`. الترحيل قابل لإعادة التشغيل، ويطبع أعداد السجلات فقط دون عرض محتواها أو بيانات الاتصال.

**تنبيه:** هذه خطوة نقل بيانات فقط. خادم التطبيق الحالي ما زال يقرأ ويكتب إلى `data/gold-signal.sqlite`؛ لا تحذف SQLite ولا تتوقع أن يعرض التطبيق بيانات Atlas حتى تكتمل ترقية طبقة التخزين واختبارها. لا تُعدّل إعدادات الخادم بحيث يبدو MongoDB متصلًا قبل إتمام هذه الخطوة.

## طبقة البيانات الجديدة (MongoDB) — إضافة بدون تغيير البوت

أضفنا طبقة MongoDB جديدة تمامًا تحت `mongo/` مع تحققات $jsonSchema وأدوار منع التعديل وفواتير سلامة (ledger) ومقيّم واحد ومركز تقارير واحد. البوت الحالي لا يستخدمها: لا يوجد dual-write، و`MONGO_DATA_LAYER_ENABLED` افتراضيًا `false` ومخصص للربط المستقبلي فقط. التصميم والافتراضات والأسئلة المفتوحة موثقة في `docs/data-layer.md`.

قبل أي نشر، افحص توافق Deployment (يحتاج replica set، وليس standalone):

```bash
npm run mongo:doctor
npm run mongo:migrate -- status
npm run mongo:migrate -- up
npm run mongo:verify-ledger
npm run mongo:integrity -- --evaluator v1.0.0
npm run mongo:report -- --strategy all --since 2026-01-01 --evaluator v1.0.0
```

حالة Atlas الحالية: الهجرات الأربع مطبّقة، والمجموعات والفهارس والـ views وقاموس البيانات موجودة، ولم تُمسّ البيانات القديمة. فئة Atlas لا تسمح بإنشاء الأدوار المخصصة (`createRole`/`dropRole` ممنوعان)؛ لذلك سُجّلت فجوة `custom_roles_unavailable` في `deployment_gaps`، ويعرض `npm run mongo:doctor` تقريرًا بـ `ok:false` لهذا السبب. يجب إبقاء `MONGO_DATA_LAYER_ENABLED=false` حتى تُفرَض الأدوار في بيئة تدعمها؛ البوت الحالي يقرأ ويكتب SQLite فقط.

استيراد السجلات القديمة اختياري ومخفي افتراضيًا، وكل سجل يُوسم `legacy_unverified=true` و`evaluator_version="legacy-unverified"` ولا يدخل تقارير المقيّم الجديد إلا مع `--include-legacy`:

```bash
npm run mongo:import-legacy                       # عرض الأعداد فقط، بدون كتابة
node mongo/import-legacy.mjs --confirm-import      # كتابة صريحة فقط
```

الاختبارات: `npm test` (57 ناجحًا افتراضيًا، و66 عند ضبط `TEST_MONGODB_URI` على replica set تجريبي مع تفعيل المصادقة؛ تتخطى اختبارات التكامل التسعة تلقائيًا بدونه). تتضمن اختبارات التخريب: رفض update/delete من `app_writer`، رفض الوثائق الغلط والمكررة، تحديد أول تضارب في `verify-ledger` بعد التلاعب أو حذف سطر، سلامة 50 إدخال متوازي، ذرّية الـ transaction عند قتل العملية، واكتشاف الناتج التالف عبر فحص النزاهة، إضافة إلى تطابق المقيّم حرفيًا عند تكرار golden dataset. اختبارات التكامل تعيد ضبط قاعدة الاختبار فقط (اسمها يجب أن يحتوي على `test`)، ولا تلمس `MONGODB_URI` أو SQLite. لتشغيلها يدويًا شغّل `node mongo/seed-fixtures.mjs --reset` ثم `npm test`. لم تُطبّق أي هجرة على Atlas أثناء هذا العمل، ولم يُحذف أو يُعدّل أي سجل موجود.

لتمكين فلتر الأخبار، سجّل للحصول على مفتاح FRED API، ثم انسخ `.env.example` إلى `.env` وضع المفتاح في `FRED_API_KEY`. لا تشارك المفتاح في المحادثة أو المستودع؛ ملف `.env` مستثنى من Git.

```bash
npm install
npm run dev
```

الأمر يشغل واجهة Vite وخادم API/التسجيل معًا. افتح الرابط الذي يعرضه Vite. للتشغيل الإنتاجي:

```bash
npm run build
npm start
```

## النشر على Vercel

استورد المستودع في Vercel؛ الإعدادات موجودة في `vercel.json` (Vite + `dist`). Vercel يستضيف **الواجهة فقط**: خادم API هو عملية Node دائمة تقرأ وتكتب SQLite وتستطلع السعر كل 30 ثانية، وهذا لا يعمل في بيئة serverless. لذلك شغّل `npm start` على مضيف دائم (VPS أو Render أو ما شابه) ثم اضبط متغير البيئة `API_UPSTREAM_URL` في إعدادات مشروع Vercel ليشير إلى الرابط العام لذلك الخادم، مثال `https://api.example.com`. دالة `api/[...path].mjs` تعيد توجيه طلبات `/api/*` إليه، وتُرجع `503` برسالة واضحة إذا لم يُضبط المتغير. لا تضع `FRED_API_KEY` أو `MONGODB_URI` في متغيرات Vercel؛ هذه تخص الخادم الدائم فقط.

## مصدر السعر وتخزينه

- يجلب الخادم XAU/USD من `https://api.gold-api.com/price/XAU` كل 30 ثانية. السعر بالدولار لكل أونصة تروي.
- يسجل كل تحديث جديد من المزود في `data/gold-signal.sqlite` مع وقت المزود ووقت الرصد. تمنع قاعدة البيانات تكرار لقطة المزود نفسها.
- يسجل جدول `trade_price_observations` كل قراءة أثناء التوصية المفتوحة ولمدة 30 دقيقة بعد الإغلاق، ويربطها بمعرّف التوصية ومرحلتها ووقتي المصدر والرصد. يمكن تنزيل سجل كل توصية بصيغة CSV من الواجهة.
- إذا مرّ أكثر من دقيقتين بلا قراءة سعر جديدة، تتوقف إدارة TP/SL ولا يُستخدم السعر القديم لإغلاق الصفقة. عند عودة السعر تُستأنف الإدارة ويُسجل انقطاع البيانات ومدته. قد لا نعرف ما حدث داخل فترة الانقطاع.
- يحفظ SQLite كل الأسعار والتوصيات، فلا تضيع عند تحديث الصفحة أو إعادة تشغيل التطبيق. يجب أن يظل الخادم يعمل لتلقي تحديثات جديدة ومراقبة الهدف ووقف الخسارة؛ فترات توقف الجهاز أو الخادم لا يمكن استعادتها تاريخيًا من نقطة السعر العامة.
- لا تضع قاعدة `data/gold-signal.sqlite` في مستودع عام؛ مسارها مستثنى في `.gitignore`.

### دقة السعر والتكاليف

- Gold API يعيد سعرًا واحدًا إرشاديًا، ولا يعيد bid/ask أو تنفيذات؛ لذلك الأسعار والإغلاقات محاكاة، وليست أسعار تنفيذ حقيقية. لا يمكن معرفة الانزلاق المحقق من دون بيانات تنفيذ فعلية.
- تحفظ التوصية نتيجة إجمالية قبل التكلفة، وتعرض صافيًا **تقديريًا فقط** لكل أونصة. النموذج الافتراضي يضع سبريدًا تقديريًا 0.30 دولار/أونصة للذهاب والعودة، وانزلاقًا 0.10 دولار/أونصة لكل جهة، وعمولة 0.035 دولار/أونصة لكل جهة؛ الإجمالي الافتراضي 0.57 دولار/أونصة للصفقة الكاملة. هذه افتراضات عامة وليست أسعار وسيط أو قياسات مباشرة، ولا تمثل إجمالي تكلفة حجم تداولك الفعلي.
- يمكن تغيير الافتراضات محليًا في `.env` عبر `GOLD_ESTIMATED_SPREAD_USD_PER_OUNCE` و`GOLD_ESTIMATED_SLIPPAGE_USD_PER_OUNCE_PER_SIDE` و`GOLD_ESTIMATED_COMMISSION_USD_PER_OUNCE_PER_SIDE`. تُحفظ القيم المستخدمة مع كل توصية حتى لا تتغير نتائجها التاريخية عند تعديل الإعدادات. لا تسجل القيم على أنها تكاليف فعلية.
- عند أول تشغيل لهذا الإصدار، تُطبّق هذه التقديرات مرة واحدة على التوصيات القديمة ذات التكلفة المجهولة، مع إبقاء نتيجة السعر الإجمالية كما هي وإضافة صافي تقديري منفصل؛ لذلك لا تعني البيانات القديمة تنفيذًا فعليًا أو تكلفة وسيط معروفة.

### الحساب المحاكاة الوهمي

- يبدأ الحساب المحاكاة بـ **$1,000** ويستخدم قاعدة حجم ثابتة: **0.01 لوت لكل كامل $100** من الرصيد، بحد أدنى 0.01 لوت.
- مثال افتراضي: رصيد $1,000 = 0.10 لوت؛ رصيد $1,150 = 0.11 لوت؛ رصيد $50 = 0.01 لوت. افتراض العقد هنا 100 أونصة لكل لوت، قابل للتغيير فقط إذا عُدّل نظام العقد للوسيط.
- النقطة الواحدة هنا تعني حركة سعر بقيمة دولار واحد للأونصة الواحدة. الربح بالدولار = الحركة × الكمية المقفلة بالأونصات؛ الصافي يطرح التكلفة التقديرية لنفس الكمية.
- عند TP1/TP2 تُضاف أرباح الأثلاث المقفلة مباشرة إلى سجل الصفقة والحساب المحاكاة؛ عند TP3 أو الوقف أو مهلة 120 دقيقة تُغلق الكمية وتُحسب النتيجة النهائية والرصيد.
- الحساب المحاكاة لا ينفذ أوامر ولا يثبت ربحًا حقيقيًا، ولا يتعامل كمرجع لتنفيذات وسيط حقيقية.

## مقارنات الاستراتيجيات

- يحتفظ المشروع بالاستراتيجية الأساسية `SMA 5/12` ويضيف مستودعًا منفصلًا لكل من `SMA 10/20` و`Donchian 20` و`RSI 14` و`MACD 12/26/9`.
- تستخدم استراتيجيتا المتوسطات مقارنة المتوسط القصير بالمتوسط الطويل مع اتجاه السعر داخل النافذة، وتستخدم Donchian 20 اختراق أعلى/أدنى آخر 20 قراءة. `RSI 14` يستخدم تنعيم Wilder القياسي (بذرة المتوسط الحسابي لأول 14 تغيرًا ثم `alpha = 1/14`) مع حدود 55 للشراء و45 للبيع. `MACD 12/26/9` يستخدم EMA المُهيَّأ بمتوسط أول فترة للخطين السريع والبطيء، وخط إشارة هو EMA9 لخط MACD نفسه؛ يحتاج 35 قراءة على الأقل.
- يبدأ كل حساب مستقل برأس مال افتراضي قدره $100 ويستخدم مهلة 120 دقيقة وTP/SL 1R/2R/3R التي يطبقها مشروع التداول الرئيسي.
- لكل استراتيجية ثلاثة نماذج حجم منفصلة:
  - مخاطرة 1% من رصيد الحساب عند الدخول.
  - مخاطرة 2% من رصيد الحساب عند الدخول.
  - 0.01 لوت لكل كامل $100، بحد أدنى 0.01 لوت؛ الافتراض هو 100 أونصة لكل لوت.
- الاستراتيجيات الخمسة × النماذج الثلاثة (15 حسابًا) لا تشترك بالأرباح أو التوقفات أو الرصيد، وتُعيد المحاكاة بناءً على بيانات السعر التاريخية والحالية الموجودة في SQLite. تُنشأ صفقات المقارنة مرة واحدة عند التشغيل، ثم تُحدَّث تدريجيًا مع كل قراءة سعرية جديدة.
- تُعتبر القراءة "قادمة" مكرّرة أو قديمة إذا كانت بنفس سعر القراءة السابقة أو وصلت بعد أكثر من 15 دقيقة منها؛ لا تُفتح صفقة مقارنة على مثل هذه القراءة، ولا يُنهى الوقف الزمني لصفقة مفتوحة عليها. ده بيمنع تسجيل خسارة تكلفة فقط لصفقة سعرها ما اتغيرش.
- توجد فجوة معروفة: تاريخ Gold API يعتمد مدة وجود الخادم، ولا يحتوي على بيانات خارج نافذة الجمع والقراءات غير الموجودة لا يمكن استعادتها.

## فلتر الأخبار الاقتصادية

- مصدر التقويم هو FRED `releases/dates` مع `include_release_dates_with_no_data=true`، ما يسمح بجلب تواريخ الإصدارات المنشورة مسبقًا.
- يحتاج الفلتر مفتاح `FRED_API_KEY` محليًا. من دون المفتاح أو إذا فشل جلب التقويم/أصبح أقدم من 24 ساعة، يتوقف فتح التوصيات الجديدة؛ تستمر إدارة الصفقة المفتوحة وفق TP/SL.
- يصنف المشروع أسماء إصدارات أمريكية محددة (CPI وEmployment Situation وPCE وGDP وPPI ومبيعات التجزئة وEmployment Cost Index) على أنها عالية التأثير. هذه قائمة داخلية وليست تصنيفًا يقدمه FRED. لا يعتمد إدخال FOMC اليومي غير الدقيق في FRED كتاريخ اجتماع.
- نقطة النهاية توفر **التاريخ فقط**؛ لا توفر في هذا المسار ساعة الإصدار أو التوقع أو النتيجة أو عناوين الأخبار. لذلك يُوقف فتح التوصيات طوال يوم الإصدار حسب تاريخ `America/New_York`، ثم يعود الفلتر للسماح بتوصيات جديدة في اليوم التالي إذا كان التقويم محدثًا. ليس هذا تحليلًا لاتجاه الخبر، ولا يغطي اجتماعات FOMC بدقة أو الأخبار العاجلة والأحداث غير المجدولة.
- وثائق المصدر: [FRED release dates](https://fred.stlouisfed.org/docs/api/fred/releases_dates.html) و[مفاتيح FRED API](https://fred.stlouisfed.org/docs/api/api_key.html).

## الاستراتيجية وقواعد إغلاق التوصية

- تحتاج الإشارة 12 قراءة محفوظة. يُقارن متوسط آخر 5 قراءات بمتوسط آخر 12، مع اتجاه التغير بين أول وآخر قراءة: متوسط قصير أعلى والتغير موجب = شراء؛ متوسط أقصر أدنى والتغير سالب = بيع؛ وما عدا ذلك انتظار.
- تُنشأ توصية عند الانتقال إلى شراء أو بيع فقط، وبحد أقصى توصية واحدة مفتوحة. يتم تجاهل الإشارات الجديدة حتى إغلاق المفتوحة.
- إدارة الصفقات الجديدة تستخدم مخاطرة ابتدائية `R = 0.5%` من سعر الدخول، وتقسم الكمية افتراضيًا إلى ثلاثة أجزاء متساوية:
  - `TP1 = 1R` (0.5% باتجاه الصفقة): إغلاق ثلث الكمية وتحريك الوقف إلى سعر الدخول.
  - `TP2 = 2R` (1%): إغلاق ثلث آخر وتحريك الوقف إلى سعر TP1.
  - `TP3 = 3R` (1.5%): إغلاق الكمية المتبقية وإنهاء التوصية.
  - مستويات البيع عكس مستويات الشراء. إذا وصل السعر إلى الوقف، تغلق الكمية المتبقية ويُحسب العائد النهائي من مجموع الأرباح/الخسائر الجزئية نسبةً إلى حجم الصفقة الأصلي.
- تحريك الوقف مرتبط بالأهداف: بعد TP1 ينتقل إلى الدخول، وبعد TP2 ينتقل إلى TP1. إذا بقيت التوصية مفتوحة بعد 120 دقيقة، تُغلق محاكاة عند أول قراءة حديثة متاحة بعد المهلة؛ لا تُغلق على سعر قديم أثناء انقطاع المصدر.
- يسجل جدول `recommendation_events` كل هدف جزئي وتغيير للوقف وإغلاق عند الوقف، مع السعر المرصود والكمية والعائد الجزئي ووقت الحدث. تعرض الواجهة سجل الأحداث لكل توصية.
- تُقيّم المستويات عند وصول قراءة جديدة من المصدر فقط. إذا قفز السعر عبر أكثر من مستوى بين قراءتين، لا تتوفر بيانات الحركة داخل الفاصل؛ ويُسجل السعر المرصود عند الفحص لكل مستوى تم تجاوزه. النتائج محاكاة من سعر عام، وليست أسعار تنفيذ أوامر.
- عند بدء الإصدار الجديد، تُحوّل التوصية المفتوحة القديمة تلقائيًا إلى الأهداف الثلاثة مع الحفاظ على سعر الدخول ووقفها الابتدائي؛ ويظل سجل التوصيات المغلقة القديمة كما هو.
- صفحة السجل تعرض آخر 100 توصية، لكن قاعدة البيانات تحتفظ بالسجل الكامل.

هذه قواعد توضيحية غير مختبرة وليست استراتيجية تداول معتمدة أو نصيحة مالية. السعر الملتقط لا يضمن سعر تنفيذ لدى وسيط، ولا يحسب السبريد أو الانزلاق، ولا يرسل أوامر تداول. نقطة السعر العامة موثقة لدى [Gold API](https://gold-api.com/docs).
